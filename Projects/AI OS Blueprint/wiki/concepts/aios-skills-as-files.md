# Skills as files

**Definition:** a skill is a markdown document describing one repeatable process ("when I ask for X, do it this way"). It is a mini map of content for a process, not a feature of any AI tool.

## What the sources say
- How to make one: do the task with AI until you like the result, then ask AI to turn what you just did into a skill with a name (e.g. `screenshot-renamer`) (see [[src-2026-10-22-nm-cowork-80]]).
- Skills can then run on request ("organise these screenshots") or on a **schedule** (1st of the month, 9 am; daily brief at 6 am) (see [[src-2026-10-22-nm-cowork-80]], [[src-2026-10-22-nm-obsidian-cowork-life]]).
- They are text, so they travel to any AI tool; store them in an AIOS skills folder and list them in the [[aios-skill-map]] (see [[src-2026-10-22-nm-3-file-ai-system]]).
- Use AI to write and review skills, but keep them in your system, not the tool's: convenient once, a trap forever after (see [[src-2026-10-22-nm-obsidian-cowork-life]]).
- Start with one or two (daily-note structure, how to summarise) (see [[src-2026-10-22-nm-3-file-ai-system]]).
- Template: [[aios-kit-skill-template]].

## Synthesis
For MSK AI OS, skills fit naturally as `wiki`-adjacent markdown (e.g. a root `skills/` or `AIOS/skills/` folder). Good first candidates are processes already written down in the root `CLAUDE.md`: ingest, lint, new project, hot-cache refresh. See [[aios-msk-adoption-plan]].
